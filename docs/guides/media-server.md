## 1. الصورة الكاملة

```
                        ┌──────────────────────── خادم المنظومة (الشبكة المحلية للديوان) ────────────────────────┐
 هاتف المواطن ─WHIP───►│                                                                                         │
 هاتف الفريق  ─WHIP───►│  Caddy :443 ──► MediaMTX 1.21.2 ──(كل نشر وكل مشاهدة)──► API: /internal/mediamtx/auth   │
 كاميرا الحماية ─RTSP─►│                   │   │   │                                                             │
 كاميرا مؤسسة ─RTSP──►│                   │   │   └─► التسجيل fMP4 ─► العامل: بصمة SHA-256 ─► المخزن S3         │
   (عبر جسر المؤسسة)   │                   │   └─────► كاشف النار والدخان (vision) ─► تنبيه                      │
 درون ──RTSP/RTMP─────►│                   └─────────► WHEP / HLS ─► جدار البث في اللوحة (رمز 5 دقائق)          │
 حساس ──HTTP موقّع────►│  البوابة الصغيرة :8088 ──► API: /internal/sensors/readings                             │
 برج مراقبة ─HTTP────►│  البوابة الصغيرة :8088 ──► API: /internal/towers/events                               │
                        └─────────────────────────────────────────────────────────────────────────────────────────┘
```

**ثلاث قواعد تحكم كل شيء:**

1. **MediaMTX لا يقرر شيئا بنفسه.**
   - عند كل نشر وكل مشاهدة، يسأل المنظومة: هل يحق لهذا؟ فتجيب نعم أو لا.
   - لا يوجد في MediaMTX حساب ولا كلمة مرور ثابتة. كل الصلاحيات في المنظومة.
2. **كل مصدر مسجَّل أولا.**
   - المسار الوحيد المقبول هو `live/<معرّف>`، والمعرّف تنشئه المنظومة.
   - كل مصدر له رمز نشر خاص به، يُعرض مرة واحدة، ولا يُحفظ إلا مُجزَّأ (hash).
3. **كل بث يُسجَّل كدليل.**
   - التسجيل مقاطع من 60 ثانية.
   - كل مقطع يُحسب له بصمة SHA-256 ثم يُنقل إلى المخزن.
   - المشاهدة والتنزيل مسجّلان في سجل التدقيق باسم العون.

## 2. عناصر المنظومة: الوصف والإصدار والمصدر

| العنصر | ما يفعله | الإصدار | المصدر والرخصة |
|---|---|---|---|
| **MediaMTX** | خادم الوسائط: يستقبل WHIP وRTSP وRTMP وSRT، ويوزّع WebRTC/WHEP وHLS، ويسجّل fMP4 | 1.21.2 (صورة `bluenviron/mediamtx:1.21.2-ffmpeg`، مثبّتة ببصمتها) | github.com/bluenviron/mediamtx، رخصة MIT |
| **FFmpeg** | داخل صورة MediaMTX، وفي جسر الكاميرات والمرحِّل: نقل الفيديو وإعادة تغليفه | المرفق بالصورة (7.x) | ffmpeg.org، رخصة LGPL/GPL |
| **Caddy** | البوابة الأمامية: الشهادات، ويمرّر فقط مسارات الوسائط `/live/<id>/whip\|whep` وملفات HLS | 2.11 (`caddy:2.11-alpine`) | caddyserver.com، رخصة Apache-2.0 |
| **API (FastAPI)** | يقرر كل نشر ومشاهدة، ويصدر الرموز، ويستقبل أحداث MediaMTX | المنظومة (`ehimaya/api`) | هذا المستودع |
| **العامل (worker)** | ينقل مقاطع التسجيل إلى المخزن بعد حساب بصمتها، ويحذف النسخة المحلية | المنظومة | هذا المستودع |
| **المخزن S3 (SeaweedFS)** | التسجيلات والصور، بروابط مؤقتة | 4.48 (`chrislusf/seaweedfs:4.48`) | github.com/seaweedfs/seaweedfs، رخصة Apache-2.0 |
| **كاشف النار والدخان (vision)** | يقرأ البث داخليا (RTSP)، ويؤكد النار أو الدخان في 3 من آخر 5 صور | المنظومة (`ehimaya/vision`، النموذجان fire-smoke وperson) | هذا المستودع؛ النماذج مع بطاقاتها في «بطاقات النماذج» |
| **قارئ مواقع الدرون (drone-telemetry)** | يقرأ بيانات KLV (MISB ST 0601) من بث الدرون عبر SRT، ويرسل الموقع ومخروط الكاميرا | المنظومة (صورة vision، الأمر `app.telemetry serve`) | هذا المستودع |
| **البوابة الصغيرة (sensor-gateway)** | تستقبل قراءات الحساسات وأحداث الأبراج على الشبكة المحلية، وتحفظها على القرص، ثم تمرّرها | المنظومة (Python وحده) | `services/sensor-gateway` |
| **جسر الكاميرات (camera-bridge)** | على شبكة المؤسسة: يحوّل إنذار الكاميرا الحرارية إلى إنذار موقّع، ويدفع الفيديو بعده | المنظومة (Python وحده، وFFmpeg) | `services/camera-bridge` |
| **مرحِّل الكاميرا (camera-relay)** | لكاميرا لا تعرف الدفع: يسحب منها RTSP ويدفعه إلى MediaMTX | سكربت FFmpeg | `infra/camera-relay/camera-relay.sh` |
| **محاكي البث (stream-sim)** [SIM] | كاميرا تجريبية للتطوير فقط، ممنوعة في الإنتاج | المنظومة | `infra/stream-sim` |
| **chrony / gpsd** | ساعة موحّدة للخادم والأجهزة: يُرفض كل ما يسبق ساعة الخادم بأكثر من 10 دقائق | حزم Ubuntu 24.04 | chrony-project.org، gpsd.io |

جميع الصور مثبّتة ببصماتها (`@sha256:…`) في `infra/compose.yml`. لا تُحدَّث صورة إلا بطلب دمج يغيّر البصمة، وبعد مرور الفحص الأمني (Trivy) في التكامل المستمر.

## 3. بناء الخادم: خطوة بخطوة

### 3.1 العتاد

| البند | حتى 10 كاميرات و50 حساسا | لـ 200 بث متزامن (NFR-03) |
|---|---|---|
| المعالج | 8 أنوية x86-64 | 16–32 نواة، أو بطاقة رسوميات لكاشف النار (`infra/compose.gpu.yml`) |
| الذاكرة | 32 GB | 64 GB |
| قرص النظام | SSD بسعة 512 GB | SSD بسعة 1 TB |
| قرص البيانات | 2–4 TB | 8 TB أو مخزن S3 منفصل |
| الشبكة | 1 Gb/s | 10 Gb/s، أو عدة منافذ |
| الكهرباء | UPS يكفي 30 دقيقة | UPS ومولّد |

**حساب عرض النطاق:**

- كاميرا 1080p بترميز H.264 تحتاج 2 إلى 4 Mb/s للنشر.
- كل مشاهد يأخذ نسخة كاملة بالمعدّل نفسه. الحد 16 مشاهدا لكل بث (`maxReaders`).
- التسجيل بـ 4 Mb/s يساوي 1.8 GB في الساعة لكل كاميرا.

البث المتواصل لمئات الكاميرات غير ممكن: 1400 كاميرا تعني 0.7 إلى 4 Gb/s. لذلك كاميرات المؤسسات لا تبث إلا بعد إنذار (جسر الكاميرات).

### 3.2 النظام وDocker

```bash
# Ubuntu Server 24.04 LTS، بعد التحديث (install-guide.md §2 و§3)
sudo timedatectl set-timezone Africa/Tunis
sudo apt update && sudo apt -y upgrade
sudo apt install -y ca-certificates curl git chrony ufw iptables-persistent

# Docker من مستودعه الرسمي (install-guide.md §5)
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu noble stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt update && sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker $USER && newgrp docker
docker version && docker compose version          # Compose 2.24 أو أحدث
```

خادم بلا إنترنت: تُنقل حزم Docker والصور بمفتاح USB (`field-guide-sensors.md` §6.4 و§6.6).

## 4. مصادر الفيديو، كل واحد على حدة

### 4.1 كاميرات الحماية المدنية الثابتة (الطرقات، الغابات، المخازن)

1. **التسجيل:** مسؤول العمليات في **اللوحة ← البث المباشر ← تسجيل كاميرا**. يُدخل الاسم والولاية والموقع.
2. يظهر **مرة واحدة**: عنوان RTSP، وعنوان RTMP، ورمز النشر. يُحفظ الرمز في الكاميرا فورا.
3. **في الكاميرا:** إعدادات «RTSP Push» أو «Stream to server»:
   - العنوان: `rtsp://192.168.60.1:8554/live/<المعرّف>`؛
   - اسم المستخدم: أي قيمة؛
   - كلمة المرور: الرمز؛
   - النقل: TCP؛
   - الترميز: H.264، 1080p أو 720p، و2–4 Mb/s.
4. **كاميرا لا تعرف الدفع** (RTSP على الكاميرا فقط): المرحِّل بجانبها:

   ```bash
   ffmpeg -rtsp_transport tcp -i rtsp://<user>:<pass>@<cam-ip>/stream1 -c copy \
     -f rtsp -rtsp_transport tcp rtsp://cam:<الرمز>@192.168.60.1:8554/live/<المعرّف>
   ```

5. **الكشف:** إن كان كاشف النار مفعّلا، يُقرأ البث آليا، وأي نار مؤكدة تُبلَّغ إلى القاعة المختصة.

### 4.2 كاميرات المؤسسات

نوعان، يُختار أحدهما عند التسجيل («من يتابع الجهاز»):

| النوع | البث | الإنذار |
|---|---|---|
| تتابعه الحماية المدنية | متواصل، كالفقرة 4.1 | إلى القاعة فورا |
| على ملك المؤسسة | **لا بث متواصل**: يبدأ البث 10 دقائق بعد الإنذار فقط | مسؤول السلامة 60 ثانية، ثم صاحب المؤسسة 60 ثانية، ثم القاعة آليا |

- **الكاميرا الحرارية أو كاميرا كشف النار المدمج** (Hikvision، Dahua، وغيرهما) ترتبط بـ**جسر الكاميرات** على شبكة المؤسسة:
  - المنفذ 8099 على شبكة المؤسسة؛
  - الإنذار يُرسل موقّعا بمفتاح الكاميرا عبر HTTPS؛
  - الفيديو يُدفع بعد الإنذار.

  التنصيب كاملا في `docs/guides/camera-bridge.md`.
- **ما تراه المؤسسة:** صورة الإنذار على هاتف مسؤول السلامة وصاحب المؤسسة (شاشة التنبيه المسبق)، لا البث المباشر.

### 4.3 الدرون (إبان التشغيل والتدخل)

1. **التسجيل:** مسؤول العمليات في **اللوحة ← الدرون ← تسجيل درون**. يظهر عنوان النشر ورمزه مرة واحدة.
2. **من تطبيق الطيار أو المحطة الأرضية:**
   - RTMP (تطبيقات DJI، OBS): `rtmp://192.168.60.1:1935/live/<المعرّف>?token=<الرمز>`؛
   - أو RTSP كالكاميرا (الفقرة 4.1).
3. **الموقع ومخروط الكاميرا:**
   - إن أرسل الدرون بيانات KLV (MISB ST 0601) في MPEG-TS، يقرؤها قارئ المواقع ويعرضها على الخريطة؛
   - دون ذلك يظهر الفيديو دون موقع.
4. **مناطق العمل والحظر:** يرسمها مسؤول العمليات. خروج الدرون منها يرفع تنبيها يقرّ به عون القاعة.
5. **انقطاع الرابط:** يعود الدرون بالرمز نفسه دون تسجيل جديد. **إيقاف البث من اللوحة** يُبطل الرمز نهائيا.
6. **لا أمر يُرسل إلى الدرون أبدا:** الطيار وحده يقوده. هذا الشرط مثبّت باختبار في المنظومة.

### 4.4 كاميرات الهواتف، حسب صفة المستعمل

| المستعمل | من أين يبث | متى | الحدود | من يرى |
|---|---|---|---|---|
| **المواطن** (ويشمل المتطوع حين يبلّغ) | تطبيق المواطن ← بلاغ ← «البث المباشر مع البلاغ» | مع بلاغ قائم فقط | WHIP وحده، 15 دقيقة، 6 بثوث في الساعة، الموقع يتبع البث | قاعة الولاية المختصة |
| **قائد الفريق الميداني** | تطبيق الأعوان ← المهمة ← «البث المباشر» | أثناء مهمة نشطة | هاتف مسجّل في المناوبة | القاعة المختصة، والقائد الميداني |
| **الطبيب المتطوع وطبيب الحماية** | لا بث فيديو | — | الصور والرسائل حسب ملف الحالة | — |
| **عضو المؤسسة** | لا بث من الهاتف | — | يرى صورة الإنذار المسبق فقط | — |

**تشغيل البث من الهاتف:**

- يحتاج المنفذ 8189/udp مفتوحا إلى عنوان `MEDIAMTX_WEBRTC_HOSTS`.
- الشبكات التي تحجب UDP تحتاج خادم TURN (`MTX_WEBRTCICESERVERS2`)، أو WebRTC عبر TCP (`MTX_WEBRTCLOCALTCPADDRESS=:8189`).

## 5. الحساسات: القائمة والإدارة

| النوع | المفتاح | الوحدة | الاستعمال |
|---|---|---|---|
| مقياس المطر (ساعة) | `rain_1h` | mm | الفيضانات وانجراف التربة |
| منسوب المياه | `water_level` | m | الأودية والسدود والقنوات |
| الحرارة | `temperature` | °C | الغابات والمخازن وموجات الحر |
| برج المراقبة [SIM] | حدث من حاسوب الحافة | — | كشف الدخان في الغابات (`sensor-gateway.md` §7) |
| الدرون | موقع ومخروط الكاميرا | — | المتابعة أثناء التدخل (الفقرة 4.3) |

### 5.1 دورة حياة الحساس

1. **التسجيل:** مسؤول العمليات في **اللوحة ← الحساسات ← تسجيل حساس**. يُدخل النوع والموقع والعتبتين («انتباه» و«إنذار»).
   - يظهر مفتاح التوقيع **مرة واحدة**، ويُحفظ مشفّرا في المنظومة وحدها.
2. **الربط:** يرسل الحساس قراءته موقّعة بـ HMAC-SHA256 إلى `http://192.168.50.1:8088`. الصيغة والأمثلة في `sensor-gateway.md` §4.
3. **المستويات:**
   - عادي؛
   - انتباه؛
   - إنذار؛
   - صامت: لم تصل قراءة في الأجل؛
   - معطَّل.
4. **تجاوز العتبة:** يصبح **اقتراحا** في مركز التنبيهات، لا رسالة إلى المواطنين. يراجعه عون، ثم يمر بمسار موافقة شخصين.
5. **تجديد المفتاح:** يُجدَّد من صفحة الحساس، فيبطل المفتاح القديم فورا.
6. **التعطيل:** من صفحة الحساس. تُرفض قراءاته، ويبقى سجلّه.

### 6.1 الجدول

| ما يُرى | عون القاعة | مسؤول العمليات | القائد الميداني | اللجان المحلية والمركزية | الوالي والوزير | مدير النظام (تقني) |

**النطاق والحدود:**

- **النطاق الجغرافي:**
  - القاعة الجهوية ترى ولايتها فقط، بأمن الصفوف في قاعدة البيانات (RLS)؛
  - القاعة المركزية ترى كل الولايات.
- **الحدود الثابتة:** لا يرى الوالي والوزير المعطيات الشخصية أبدا، ولا يملك الحساب التقني أي حق تشغيلي. لا يرفع أي منح هذه الحدود.

### 6.2 متى

| الحالة | ما يحدث |

## 7. التفعيل والتعطيل من قبل مدير النظام

مدير النظام لا يشاهد البث (حساب تقني). يتحكم في **ما يظهر ولمن**، من **اللوحة ← الصلاحيات ← كتالوج الوظائف**:

| الوظيفة في الكتالوج | ما تشمله |
|---|---|
| `streams` (صفحة «البث المباشر») | القائمة والتفاصيل |
| `streams.watch` | زر «مشاهدة البث» |
| `streams.share` | «بدء بث وتسجيل الكاميرات»، وتجديد مفتاح الجسر |
| `streams.stop` | «إيقاف البث» |
| `sensors`، `sensors.manage`، `sensors.key` | صفحة الحساسات، وتسجيلها وعتباتها، ومفاتيحها |
| `towers`، `towers.manage`، `towers.key` | أبراج المراقبة |
| `drones`، `drones.register`، `drones.zones`، `drones.ack` | الدرون، وتسجيله، ومناطقه، والإقرار بتنبيهاته |
| `field_missions.stream` (تطبيق الأعوان) | البث من هاتف الفريق |
| `citizen_reports.video` (تطبيق المواطن) | البث مع البلاغ، يُغلق للجميع أو لصفة (مواطن، متطوع) |

**لكل قاعدة:**

1. **المنح أو الإخفاء:** يُختار «منح» أو «إخفاء».
2. **لمن:** دور، أو ولاية، أو شخص بعينه.
3. **المدة:** تاريخ بداية ونهاية.
4. **السبب:** إجباري، ويُسجَّل في سجل التدقيق.

**المعاينة:** «معاينة» تعرض ما سيراه دور أو شخص قبل التفعيل.

**القيود:**

- الممنوح يعمل «بصفة» الدور المذكور في الكتالوج، ولا يتجاوز الحدود الثابتة (الفقرة 6.1).
- أزرار سلامة الطاقم (طلب التعزيز، الخطر على الطاقم) ونداء الاستغاثة **لا تُخفى أبدا**.

**التعطيل التقني:**

| الخدمة | طريقة الإيقاف | ما يحدث |
|---|---|---|
| كاشف النار | `VISION_SERVICE_URL` فارغ | البث يعمل دون كشف |
| البوابة | إيقاف ملف `sensors` | لا قراءات جديدة |
| قارئ الدرون | إيقاف ملف `drones` | الفيديو دون موقع |

## 8. التحقق اليومي والأعطال

```bash
F="-f infra/compose.yml -f infra/compose.prod.yml -f infra/compose.lan.yml"
docker compose --env-file .env $F logs --since 1h mediamtx | grep -E "ERR|WAR"
docker compose --env-file .env $F logs --since 1h api | grep -E "mediamtx\.auth_denied|camera_bridge\.refused"
curl -s http://192.168.50.1:8088/health                    # {"status":"ok","queued":0,...}
df -h /var/lib/docker                                       # مساحة التسجيلات المؤقتة
chronyc tracking                                            # Leap status: Normal
```

| العَرَض | السبب الأرجح |
|---|---|
| الكاميرا مرفوضة (`bad_publish_token`) | رمز خاطئ أو أُبطل: أعد التسجيل أو جدّد |
| الهاتف يتصل ولا فيديو | 8189/udp مغلق، أو `MEDIAMTX_WEBRTC_HOSTS` غير صحيح |
| البث يبقى «في الانتظار» | الناشر لم يتصل. ينتهي البث بعد 10 دقائق. |
| لا تنبيه نار | حالة الكشف `disabled` أو `requested`؛ تُراجع `VISION_SERVICE_URL` |
| قراءات الحساسات متأخرة | `queued` يرتفع: الرمز `SENSOR_GATEWAY_TOKEN`، أو حاوية `api` متوقفة |
| حساس «صامت» | ساعته منحرفة أكثر من 10 دقائق، أو الشبكة مقطوعة |

الجدول الكامل في `docs/streaming.md` §7.
