# CI/CD: من الدفعة إلى الخادم

طلب يامن، 2026-11-08: «CI/CD عامة وشاملة».

## 1. السلسلة كاملة

```
دفعة أو طلب دمج ──► CI (ci.yml و dashboard.yml و portal.yml و mobile.yml و apk.yml)
                      │  اختبارات، أنواع، ترحيل، صور، فحص ثغرات، تراخيص، عرض الحزمة كاملة
                      ▼
               دمج في main (يامن)
                      │
وسم vX.Y.Z ──► Release (release.yml)
                      │  بناء الصور مرة واحدة ← فحص Trivy ← نشر في GHCR مع SBOM ومصدر البناء ← توقيع cosign
                      │  ← إصدار GitHub بحزمة النشر وقائمة البصمات
                      ▼
               النشر على خادم التجربة (staging) آليا، إن ضُبط
                      ▼
               النشر على الإنتاج بعد موافقة يامن في GitHub (البيئة production)
                      │  scripts/deploy.sh: يتحقق من التوقيعات ← يحفظ قاعدة البيانات ← يسحب الصور ← يرحّل
                      │  ← يشغّل وينتظر الفحوص ← يعود إلى النسخة السابقة إن فشلت
```

## 2. CI (كل دفعة وكل طلب دمج)

| المسار | الملف | ما يفحصه |
|---|---|---|
| الواجهة البرمجية | `ci.yml` (`api`) | ruff، mypy، الترحيلات صعودا ونزولا، كل الاختبارات على PostgreSQL حقيقي |
| خدمات بايثون الأخرى | `ci.yml` | notify-sim، sensor-gateway، camera-bridge، ai، vision، مع نماذجها الحقيقية |
| الصور | `ci.yml` (`image-scan`) | بناء كل صورة وفحصها بـ Trivy (CRITICAL مع إصلاح متاح = فشل) |
| سلسلة التوريد | `ci.yml` (`supply-chain`) | تدقيق الحزم، قائمة المكوّنات (SBOM)، التراخيص |
| الجودة | `ci.yml` (`quality`) | التتبع، قواعد التنبيه، إعداد Loki وAlloy، سكربت النشر (shellcheck) وملفات العمل |
| الحزمة كاملة | `ci.yml` (`stack`) | عرض ملف الإنتاج وملف الإصدار، تشغيل الحزمة، سيناريو بلاغ كامل |
| الواجهات | `dashboard.yml` و `portal.yml` | lint، الأنواع، الاختبارات، البناء، اختبارات المتصفح |
| التطبيق | `mobile.yml` و `apk.yml` | تحليل Flutter، الاختبارات، بناء APK |
| التحديثات | `dependabot.yml` | اقتراح تحديث كل الحزم والصور أسبوعيا |

## 3. الإصدار (`release.yml`)

يبدأ عند دفع وسم `vX.Y.Z`، أو يدويا من Actions بذكر وسم موجود.

1. **الصور:** api (ومعها worker وmigrate)، postgres، keycloak، notify-sim، sensor-gateway، camera-bridge، ai، ai-models،
   vision، vision-models، telephony، call-sim. كل صورة تُبنى مرة واحدة، وتُفحص، ثم تُنشر باسم
   `ghcr.io/mouhabouk/ehimaya-<الاسم>:<الإصدار>` مع:
   - قائمة مكوّناتها (SBOM) ومصدر بنائها (provenance) مرفقين بالصورة؛
   - توقيع Sigstore cosign دون مفتاح، بهوية هذا الملف نفسه، فلا سر يُحفظ ولا يُسرّب.
2. **الحزمة:** ملفات compose والإعدادات والسكربتات وقائمة البصمات (`images.txt`) و`SHA256SUMS`.
3. **إصدار GitHub:** ملاحظات تلقائية (الالتزامات منذ الوسم السابق، الترحيلات الجديدة، الصور ببصماتها) والحزمة.

لوحة التحكم والبوابة تُبنيان على الخادم نفسه، لأن عناوينه وسياسة أمن المحتوى تدخل فيهما عند البناء.

## 4. النشر

### 4.1 على الخادم مباشرة

```bash
cd /opt/ehimaya
git fetch --tags && git checkout v1.2.0
scripts/deploy.sh v1.2.0
```

السكربت:

1. يتحقق من توقيع كل صورة بـ `cosign verify`، إن كان cosign مثبتا (يُنصح به في الإنتاج)؛
2. يحفظ قاعدة البيانات في `backups/predeploy-<الإصدار>.dump`؛
3. يسحب الصور، ويبني لوحة التحكم والبوابة من `.env` الخادم؛
4. يرحّل قاعدة البيانات (`migrate`)، ثم يشغّل الكل وينتظر فحوص الصحة (10 دقائق)؛
5. إن لم تصح الخدمات يعيد تشغيل النسخة السابقة (المحفوظة في `.deployed-version`).

ملفات التعريف المشغّلة افتراضيا: `monitoring` و`logs`. يغيّرها المتغير `DEPLOY_PROFILES`.

### 4.2 آليا من GitHub

لا يشتغل إلا إذا ضبط يامن هذه القيم في إعدادات المستودع:

| النوع | الاسم | القيمة |
|---|---|---|
| متغير | `DEPLOY_STAGING_HOST` | عنوان خادم التجربة (اختياري) |
| متغير | `DEPLOY_PRODUCTION_HOST` | عنوان خادم الإنتاج |
| متغير | `DEPLOY_USER`، `DEPLOY_DIR` | المستخدم (`ehimaya`) والمجلد (`/opt/ehimaya`) |
| سر | `DEPLOY_SSH_KEY` | مفتاح SSH خاص بالنشر وحده، لا يملك إلا تشغيل `scripts/deploy.sh` |
| سر | `DEPLOY_KNOWN_HOSTS` | بصمة الخادم (`ssh-keyscan`)، كي لا يُقبل خادم منتحل |

وفي **Settings ← Environments** تُنشأ البيئة `production` ويُضاف يامن مراجعا إلزاميا: كل نشر في الإنتاج ينتظر موافقته.

## 5. الرجوع

- **الصور:** `scripts/deploy.sh v1.1.0` يعيد النسخة السابقة.
- **قاعدة البيانات:** الترحيل لا يُلغى آليا أبدا. إن احتاج الرجوع إلى ما قبل ترحيل:
  `pg_restore --clean -d ehimaya backups/predeploy-v1.2.0.dump`، بعد إيقاف api وworker. تُكتب كل ترحيلات الإصدار في
  ملاحظاته ليُعرف ذلك قبل النشر.

## 6. القواعد الثابتة

- لا يُدمج أي طلب دمج إلا يامن، ولا يُنشر في الإنتاج إلا بموافقته.
- لا سر في المستودع ولا في سجلات Actions. التوقيع دون مفتاح، والنشر بمفتاح SSH محصور.
- الصور مثبتة بالبصمة في compose، وإصدارات الخدمات الخارجية في `docs/versions.md`.
