# هاتف أندرويد بوابةً للرسائل القصيرة (للعرض)

**الهدف:** عرض المنظومة برسائل حقيقية قبل فتح الرقم 198 للرسائل لدى المشغلين. يستعمل العرض هاتف أندرويد بشريحة عادية.

**ما يمر عبر الهاتف في الاتجاهين:**

- بلاغ المواطن (EH1) وخطوات الفرق (EH2) تصل إلى المنظومة عبر الهاتف.
- رد المنظومة برمز المتابعة يخرج من الهاتف نفسه.

> **عرض فقط.** في الاستغلال الفعلي تمر الرسائل عبر بوابة المشغلين على المسار `/internal/sms/inbound`. وتبقى إعدادات `SMS_PHONE_*` فارغة.

```
مواطن أو عون ──SMS──▶ شريحة الهاتف ──(تطبيق SMS Gateway، webhook موقّع)──▶ المنظومة /internal/sms/phone
                                                                                │
مواطن ◀──SMS── شريحة الهاتف ◀──(POST /message، كلمة سر)─────────────────────────┘ رمز المتابعة
```

## ما يلزم

- **هاتف أندرويد** (الإصدار 5 أو أحدث) بشريحة من أي مشغّل ورصيد رسائل. كل رد برمز المتابعة رسالة مدفوعة.
- **كابل USB** بين الهاتف والحاسوب الذي يشغّل المنظومة. ويكون الهاتف والحاسوب على نفس شبكة الـ Wi-Fi.
- **أدوات أندرويد (adb) على الحاسوب:** حزمة «Android SDK Platform-Tools» المجانية من موقع Android للمطورين.
- **تطبيق «SMS Gateway for Android»:** مفتوح المصدر بترخيص Apache-2.0، ويعمل محليا دون سحابة.
  - الموقع: https://sms-gate.app
  - الشيفرة: https://github.com/capcom6/android-sms-gateway

## 1. تجهيز الهاتف

1. نزّل ملف APK من صفحة «Releases» في المستودع أعلاه، وثبّته. يطلب الهاتف عادة السماح بالتثبيت من مصدر غير معروف.
2. افتح التطبيق، وامنحه أذونات الرسائل القصيرة والهاتف.
3. في إعدادات أندرويد، أوقف «تحسين البطارية» لهذا التطبيق حتى لا يتوقف أثناء العرض.
4. في الشاشة الرئيسية للتطبيق، فعّل **Local Server** ثم اضغط **Start**. يعرض التطبيق ثلاثة أشياء، دوّنها:
   - العنوان، مثل `192.168.1.20:8080`
   - اسم المستخدم
   - كلمة السر
5. في **Settings ← Webhooks ← Signing Key**، دوّن مفتاح التوقيع. يمكنك أيضا وضع مفتاح من اختيارك من 8 أحرف أو أكثر.

## 2. ربط الهاتف بالحاسوب

1. في الهاتف: الإعدادات ← حول الهاتف ← اضغط سبع مرات على «رقم الإصدار» حتى تظهر «خيارات المطوّر». ثم فعّل منها **تصحيح USB**.
2. صِل الكابل، واقبل طلب الثقة الذي يظهر على الهاتف.
3. في الحاسوب (PowerShell أو الطرفية):

   ```bash
   adb devices                     # يجب أن يظهر الهاتف بالحالة device
   adb reverse tcp:8000 tcp:8000   # عنوان 127.0.0.1:8000 في الهاتف يصل إلى المنظومة في الحاسوب
   ```

   أعد الأمر `adb reverse` كلما فصلت الكابل أو أعدت تشغيل الهاتف.

**لماذا الكابل؟** التطبيق لا يرسل الرسائل إلى عنوان داخل الشبكة إلا عبر HTTPS بشهادة موثوقة، والاستثناء الوحيد هو `http://127.0.0.1`. والأمر `adb reverse` يجعل المنظومة على هذا العنوان داخل الهاتف، دون شهادة ودون إنترنت.

## 3. ضبط المنظومة

أضف إلى ملف `.env` في جذر المشروع:

```bash
SMS_PHONE_SIGNING_KEY=<مفتاح التوقيع من الخطوة 1.5>
SMS_PHONE_URL=http://192.168.1.20:8080      # عنوان الهاتف في الشبكة كما يعرضه التطبيق
SMS_PHONE_USERNAME=<اسم المستخدم>
SMS_PHONE_PASSWORD=<كلمة السر>
```

ثم أعد تشغيل الخادم:

```bash
docker compose -f infra/compose.yml up -d api
```

**دون Wi-Fi مشترك:** نفّذ `adb forward tcp:8080 tcp:8080`، ثم ضع `SMS_PHONE_URL=http://host.docker.internal:8080`. هذا يعمل في Docker Desktop.

**أيّ بوابة تُستعمل للردود؟** ما دامت قيم `SMS_PHONE_*` مضبوطة، تخرج ردود المنظومة من الهاتف بدل `SMS_HTTP_URL`.

## 4. ربط الهاتف بالمنظومة (مرة واحدة)

من الحاسوب، بعنوان الهاتف واسم المستخدم وكلمة السر:

```bash
curl -X POST -u <اسم المستخدم>:<كلمة السر> -H "Content-Type: application/json" \
  -d '{"id":"ehimaya","url":"http://127.0.0.1:8000/internal/sms/phone","event":"sms:received"}' \
  http://192.168.1.20:8080/webhooks
```

## 5. التجربة

من هاتف آخر، أرسل إلى رقم الشريحة النص التالي حرفيا:

```
EH1 fire 36.80650,10.18150 10m abcdef01
```

**النتيجة المنتظرة:**

- يظهر بلاغ حريق في تونس في القاعة، بالمصدر «رسالة قصيرة».
- يصل إلى الهاتف المرسِل رمز المتابعة.

**إن لم يحدث شيء:**

- افتح في تطبيق الهاتف **Settings ← Webhooks ← Delivery queue**. تظهر هناك محاولات الإرسال وسبب كل خطأ:
  - **401:** مفتاح التوقيع غير مطابق.
  - **404:** القيمة `SMS_PHONE_SIGNING_KEY` فارغة.
  - **انقطاع الاتصال:** أعد الأمر `adb reverse`.
- الرسالة التي لا تبدأ بـ EH1 أو EH2 تُهمل، ولا تُنشئ بلاغا.

## 6. التطبيقان برقم الشريحة

يكتب التطبيقان الرسالة وحدهما عند غياب الإنترنت، فلا يكتب المواطن ولا العون شيئا. لذلك يُبنى كل منهما برقم الشريحة كما في `docs/install-guide.md` §14.2:

- **تطبيق المواطن:** `--dart-define=SMS_REPORT_NUMBER=<رقم الشريحة>`. عند غياب الإنترنت يقترح «الإرسال عبر رسالة قصيرة».
- **تطبيق الأعوان:** `--dart-define=STAFF_SMS_NUMBER=<رقم الشريحة>`. الخطوات وطلب النجدة تُرسل برسالة EH2 موقّعة بمفتاح الهاتف. ويجب أن يكون الهاتف قد اتصل بالإنترنت مرة واحدة على الأقل بعد ربطه بالحساب، حتى يتسلّم مفتاحه.

متى فُتح الرقم 198 للرسائل، يُعاد البناء بالرقم 198 وتُفرَّغ قيم `SMS_PHONE_*`.

## حدود العرض

- **الحد الأقصى للرسائل:** 10 بلاغات في الساعة لكل رقم مرسِل، و60 رسالة في الساعة لهاتف قائد الفريق.
- **التكرار:** الرسالة التي تصل مرتين لا تُطبَّق إلا مرة واحدة.
- **ما يُحفظ:** نص الرسالة لا يُحفظ، ورقم المرسِل يُحفظ مشفّرا. والمعالجة كما في البوابة الرسمية.
- **إن توقفت المنظومة أو فُصل الكابل:** يحتفظ التطبيق بالرسائل ويعيد إرسالها إلى المنظومة طوال يومين تقريبا.
