# بوابة الحساسات الصغيرة: الدليل والمتطلبات (L5b)

المراجع:
- `docs/phase-l/design-l5.md` §3.0 و§3.1؛
- قرار يامن (2026-10-28): الحساسات تبقى على الشبكة المحلية، وتصل قراءاتها إلى المنظومة عبر بوابة صغيرة على خادم MediaMTX.

كل ما يحمل وسم **[SIM]** تجريبي إلى أن تُربط حساسات حقيقية.

## 1. ما تفعله البوابة

```
الحساس (مطر، منسوب، حرارة)
   │  HTTP JSON موقّع بمفتاح الحساس، على الشبكة المحلية فقط
   ▼
البوابة الصغيرة  (خادم MediaMTX، المنفذ 8088)
   │  تتحقق من الشكل، وتحفظ القراءة على القرص، ثم تمرّرها دفعات
   ▼
المنظومة  POST /internal/sensors/readings  (رمز البوابة، ومن الشبكة المحلية فقط)
   │  تتحقق من توقيع كل قراءة ووقتها وقيمتها، وترفض المكرّر
   ▼
سجل الحساسات ← المستوى (عادي، انتباه، إنذار، صامت) ← اقتراح في مركز التنبيهات
```

- **لا تحمل البوابة مفاتيح الحساسات.** المفاتيح محفوظة مشفّرة في المنظومة وحدها، والتوقيع يُفحص هناك. فلو سُرقت البوابة لا يُسرق معها مفتاح أي حساس.
- **لا تفقد البوابة قراءة إذا انقطعت المنظومة أو الكهرباء.** القراءات تبقى في ملف على القرص، وتُرسل حين تعود المنظومة.
- **لا تتصل البوابة بالإنترنت أبدًا.** ترفض أي متصل من خارج الشبكات المحلية المسموحة، ولا تقبل في إعداداتها نطاقًا عامًا.
- **تجاوز العتبة لا يُرسل شيئًا إلى المواطن.** يصبح اقتراحًا في مركز التنبيهات يراجعه عون، ثم يمر بمسار الموافقة القائم (شخصان).

## 2. المتطلبات

### 2.1 الجهاز

| البند | الحد الأدنى | ملاحظة |
|---|---|---|
| المكان | خادم MediaMTX نفسه | أو جهاز صغير على الشبكة المحلية نفسها |
| النظام | Linux (Ubuntu 22.04 أو 24.04، Debian 12) | |
| المعالج والذاكرة | نواة واحدة و256 ميغابايت | البوابة لا تحتاج أكثر من ذلك |
| القرص | 1 غيغابايت | صف الانتظار: حتى 100 ألف قراءة، أي بضع عشرات من الميغابايتات |
| البرامج | Docker، **أو** Python 3.12 وحده | تكتفي البوابة بمكتبة Python القياسية، فلا يلزم تنزيل شيء من الإنترنت عند التشغيل |

### 2.2 الشبكة

| البند | القيمة |
|---|---|
| المنفذ الذي تستقبل عليه البوابة | 8088/tcp على واجهة الشبكة المحلية للخادم، ولا يُفتح إلا لشبكة الحساسات |
| الاتصال الخارج من البوابة | إلى عنوان المنظومة على الشبكة المحلية فقط (مثل `http://10.0.0.5:8000`) |
| الإنترنت | غير مطلوب، ويجب أن يبقى مغلقًا |
| مسار المنظومة `/internal/sensors/readings` | لا يمرّ عبر Caddy أبدًا، ولا يقبل إلا عناوين `SENSOR_GATEWAY_NETWORKS` |

مثال جدار حماية على خادم MediaMTX (شبكة الحساسات `192.168.50.0/24`):

```bash
sudo ufw allow from 192.168.50.0/24 to any port 8088 proto tcp
sudo ufw deny 8088/tcp
```

### 2.3 الساعة (مطلب مهم)

- **الشرط:** ترفض المنظومة كل قراءة يبعد وقتها أكثر من 10 دقائق عن ساعة الخادم، وهذه حماية من إعادة إرسال قراءات قديمة.
- **النتيجة:** يجب أن تكون ساعة الحساسات وساعة الخادم متزامنتين.
- **الحل:** الشبكة بلا إنترنت، فتحتاج مصدر وقت محليًا (NTP). ويمكن أن يكون:
  - خادم MediaMTX نفسه (chrony)، مضبوطًا على ساعة GPS أو على خادم وقت داخلي للديوان؛
  - أو أي خادم وقت آخر على الشبكة المحلية.
- **ضبط الحساسات:** تُوجَّه الحساسات إلى مصدر الوقت هذا.

### 2.4 الحساس

يحتاج الحساس، أو جهاز التجميع الذي يقرؤه، إلى ثلاثة أشياء:

1. إرسال طلب HTTP POST فيه JSON على الشبكة المحلية؛
2. حساب HMAC-SHA256، وهو متوفر في أغلب المتحكمات، مثل ESP32 وRaspberry Pi وأجهزة التسجيل الصناعية؛
3. ساعة متزامنة (§2.3).

إذا كان حساس المعهد الوطني للرصد الجوي أو وزارة الفلاحة لا يستطيع التوقيع، يوضع بجانب البوابة مُكيّف صغير يقرأ الحساس بطريقته ويوقّع عنه. يُبنى المُكيّف لكل مزوّد عندما تُعرف صيغته.

## 3. تسجيل حساس في المنظومة

1. يفتح مدير العمليات صفحة **«الحساسات»** في لوحة القيادة، ويضغط «حساس جديد».
2. يُدخل البيانات التالية:
   - الرمز، مثلًا `GAB-RAIN-01`، أحرف لاتينية وأرقام و`-` و`_`؛
   - الاسم والنوع:
     - مقياس مطر بـ«مم في الساعة»؛
     - منسوب ماء بـ«م»؛
     - حرارة بـ«°م»؛
   - الموقع والمزوّد؛
   - عتبتا **الانتباه** و**الإنذار**؛
   - مدة الصمت، أي بعد كم دقيقة بلا قراءة يظهر الحساس «صامتًا».
3. تعرض المنظومة **مفتاح الحساس مرة واحدة**، وهو 64 حرفًا ست عشريًا. يُنسخ إلى برنامج الحساس فورًا.
   - لا يظهر المفتاح بعد ذلك أبدًا، ولا يُكتب في سجل التدقيق.
   - إذا ضاع المفتاح أو تسرّب، يضغط مدير العمليات «تجديد المفتاح». يُعرض مفتاح جديد مرة واحدة، ويُرفض كل توقيع بالمفتاح القديم.

يرى كل قاعة جهوية حساسات ولايتها وحدها، وترى القاعة المركزية كل الحساسات.

## 4. صيغة القراءة

يرسل الحساس إلى البوابة طلب `POST http://<خادم-MediaMTX>:8088/readings`، وفيه قراءة واحدة أو دفعة حتى 500 قراءة:

```json
{"readings": [
  {"sensor": "GAB-RAIN-01", "at": "2026-10-28T21:00:00+01:00", "value": "12.5", "sig": "<64 حرفًا>"}
]}
```

| الحقل | الشرط |
|---|---|
| `sensor` | رمز الحساس كما سُجّل |
| `at` | الوقت بصيغة ISO 8601 **مع المنطقة الزمنية** (`+01:00` أو `Z`) |
| `value` | **نصّ** عشري، مثل `"12.5"` (حتى 4 أرقام بعد الفاصلة)، في المدى المعقول للنوع: المطر من 0 إلى 300 مم، والمنسوب من ‎-10 إلى 100 م، والحرارة من ‎-30 إلى 60 °م |
| `sig` | HMAC-SHA256 بمفتاح الحساس على النص `sensor|at|value` (الحقول الثلاثة كما أُرسلت حرفيًا)، بحروف ست عشرية صغيرة |

كل الحقول نصوص، والتوقيع يُحسب على النص كما أُرسل. بهذا يعطي الحساب النتيجة نفسها في أي لغة برمجة.

مثال حساب التوقيع في الطرفية:

```bash
KEY=<مفتاح الحساس>; MSG='GAB-RAIN-01|2026-10-28T21:00:00+01:00|12.5'
printf '%s' "$MSG" | openssl dgst -sha256 -mac HMAC -macopt hexkey:$KEY | awk '{print $2}'
```

ترد البوابة `202 {"queued": n}`.

**أسباب الرفض.** تتحقق المنظومة من كل قراءة على حدة، فلا تُسقط القراءة الخاطئة الدفعة كلها. والأسباب:

| السبب | المعنى |
|---|---|
| `unknown_sensor` | حساس غير مسجّل أو موقوف |
| `bad_signature` | التوقيع غير صحيح |
| `bad_time` | الوقت بلا منطقة زمنية، أو بعيد أكثر من 10 دقائق |
| `bad_value` | قيمة خارج المدى أو بصيغة غير صحيحة |
| `replay` | قراءة الحساس نفسه في الوقت نفسه وصلت من قبل |

تكتب البوابة في سجلها عدد كل سبب، ولا تكتب أبدًا مفتاحًا أو توقيعًا.

## 5. التشغيل على خادم MediaMTX

### 5.1 بـ Docker

```bash
docker build -t ehimaya/sensor-gateway services/sensor-gateway
docker run -d --name sensor-gateway --restart unless-stopped \
  -p <عنوان-الخادم-المحلي>:8088:8088 \
  -e GATEWAY_API_URL=http://<عنوان-المنظومة-المحلي>:8000 \
  -e GATEWAY_TOKEN=<نفس SENSOR_GATEWAY_TOKEN في المنظومة> \
  -e GATEWAY_ALLOW=192.168.50.0/24,172.16.0.0/12 \
  -v sensorqueue:/data ehimaya/sensor-gateway
```

وفي بيئة التطوير: `docker compose --profile sensors up -d sensor-gateway`.

### 5.2 بدون Docker (Python 3.12 وحده)

```bash
cd services/sensor-gateway
GATEWAY_API_URL=http://10.0.0.5:8000 GATEWAY_TOKEN=... GATEWAY_QUEUE=/var/lib/ehimaya/queue.sqlite3 \
  python3 -m gateway serve
```

### 5.3 الإعدادات

| المتغيّر | الافتراضي | المعنى |
|---|---|---|
| `GATEWAY_API_URL` | (إلزامي) | عنوان المنظومة على الشبكة المحلية |
| `GATEWAY_TOKEN` | (إلزامي، 24 حرفًا على الأقل) | نفس `SENSOR_GATEWAY_TOKEN` في إعدادات المنظومة |
| `GATEWAY_BIND` / `GATEWAY_PORT` | `0.0.0.0` / `8088` | واجهة الاستماع ومنفذه |
| `GATEWAY_ALLOW` | الشبكات المحلية الخاصة | من يحق له الإرسال. يُرفض أي نطاق عام عند التشغيل |
| `GATEWAY_QUEUE` | `/data/queue.sqlite3` | ملف صف الانتظار |
| `GATEWAY_QUEUE_MAX` | `100000` | الحد الأقصى للصف. عند امتلائه ترد البوابة `503` بدل أن تفقد القراءات بصمت |
| `GATEWAY_FLUSH_S` | `2` | كل كم ثانية تُرسل دفعة إلى المنظومة. إذا تعذّر الإرسال تتباعد المحاولات حتى دقيقة |

وفي إعدادات المنظومة:

| المتغيّر | المعنى |
|---|---|
| `SENSOR_GATEWAY_TOKEN` | رمز البوابة. ينشأ بالأمر `openssl rand -hex 24`. إذا بقي فارغًا، ترفض المنظومة كل قراءة |
| `SENSOR_GATEWAY_NETWORKS` | العناوين التي يقبل منها المسار الداخلي. الافتراضي هو الشبكات المحلية الخاصة |

### 5.4 المراقبة

- **صحة البوابة:** الطلب `GET http://<الخادم>:8088/health` يرد `{"status": "ok", "queued": n}`. إذا زاد `queued` باستمرار، فالمنظومة لا تستقبل: تُفحص الشبكة والرمز.
- **سجل البوابة:** يبيّن رفض المتصلين من خارج الشبكة، وردود المنظومة غير 200، وعدد القراءات المرفوضة حسب السبب.

## 6. التجربة بالمحاكي [SIM]

1. تسجّل في لوحة القيادة حساسًا أو أكثر بوسم [SIM]، وتنسخ مفاتيحها.
2. تكتب في `.env`:
   ```
   SIM_SENSORS=GAB-RAIN-01:<KEY>:rain_1h,GAB-WADI-01:<KEY>:water_level
   ```
3. تشغّل السيناريو:
   ```bash
   docker compose exec sensor-gateway python -m gateway simulate --scenario storm --steps 12 --every 5
   ```

السيناريوهات المتاحة:

| السيناريو | ما يحدث |
|---|---|
| `storm` | المطر يرتفع حتى 60 مم/س، والوادي حتى 4.5 م |
| `heat` | الحرارة تصعد حتى 47 °م |
| `calm` | لا تُتجاوز أي عتبة |

ترى القاعة في صفحة «الحساسات» الحساس ينتقل إلى **انتباه** ثم **إنذار**. ويظهر في مركز التنبيهات اقتراح يحمل وسم [SIM]، ولا يُرسل شيء إلى أحد.

## 7. ما يبقى للتجربة الميدانية

- اختيار الحساسات الحقيقية ومزوّديها، وبناء المُكيّف إن لم تستطع التوقيع (§2.4)؛
- مصدر الوقت المحلي (§2.3)؛
- قواعد جدار الحماية على خادم MediaMTX (§2.2)؛
- ضبط العتبات لكل موقع مع المختصين؛
- اختبار الانقطاع: فصل المنظومة ساعة، ثم التأكد أن كل القراءات وصلت بعد عودتها.
