# ء-حماية · لوحة التحكم المركزية (المرحلة 2)

لوحة تحكم ويب لأعوان الحماية المدنية: مؤشرات رئيسية، قائمة الحوادث، تفاصيل البلاغ وتغيير حالته، وخريطة حية،
مع تحديثات فورية عبر WebSocket. تطبّق المتطلبات FR-C-00 وFR-C-01 وFR-C-02، وتعتمد عقد الواجهة
`docs/api/phase-2-contract.md` (القسمان 3 و5).

## الميزات

- **الدخول (FR-C-00):** تحويل تلقائي إلى Keycloak (realm `ehimaya-staff`، عميل عام `ehimaya-dashboard`،
  Authorization Code + PKCE S256). المصادقة الثنائية TOTP يفرضها Keycloak نفسه. تجديد صامت للرمز
  بواسطة refresh token، وتسجيل خروج من Keycloak. صفحة «لا تملك صلاحية» إذا لم يحمل الرمز أي دور قراءة
  (`operator`، `ops_manager`، `field_commander`، `local_committee`، `central_committee`) أو لم يكن للحساب
  نطاق جغرافي (`gouvernorat_code` أو `scope_level=national`). يعرض الترويسة اسم المستخدم ونطاقه وأدواره.
- **المؤشرات (FR-C-01):** المجموع، المستلمة (في الانتظار)، قيد المعالجة والتدخل، المغلقة، متوسط زمن
  الاستجابة الأولى؛ توزيع حسب الحالة والصنف والولاية (رسوم أعمدة HTML/CSS على شكل جداول قابلة للقراءة
  بقارئ الشاشة)؛ اختيار الفترة 24 ساعة / 7 أيام / 30 يوما؛ تحديث تلقائي (مؤجَّل ثانيتين) عند كل حدث مباشر.
- **الحوادث:** جدول (وقت الاستلام، رمز التتبع، الصنف بأيقونة، نوع المبلّغ، الولاية، الحالة، عدد الوسائط)،
  تصفية متعددة حسب الحالة والصنف، الولاية (للنطاق الوطني فقط)، الفترة، بحث `q`، ترقيم بالمؤشر «تحميل المزيد».
  البلاغات الجديدة الواردة مباشرة تظهر أعلى القائمة مع إبراز وعدّاد غير مقروء، وتحترم عوامل التصفية.
- **تفاصيل البلاغ (`/reports/:id`):** كل الحقول، خريطة مصغرة، النص بلغته الأصلية، معرض الوسائط (صور، فيديو،
  صوت عبر الرابط الموقّع مسبقا، مع بصمة SHA-256 وحالة الملف)، سجل الحالات، بيانات المبلّغ أو «مجهول».
  تغيير الحالة متاح فقط للأدوار `operator`/`ops_manager`/`field_commander`، ويعرض فقط الانتقالات
  المسموح بها (`allowed_transitions` من الخادم، وإلا جدول العقد)، مع ملاحظة اختيارية وتحديث متفائل
  يُلغى عند الخطأ (409 ⇒ إعادة جلب الحالة الفعلية).
- **الخريطة الحية:** MapLibre GL مركّزة على تونس أو على ولاية المستخدم، علامات ملونة حسب الحالة مع أيقونة
  الصنف (أزرار قابلة للوصول بلوحة المفاتيح)، نوافذ منبثقة نحو التفاصيل، نفس عوامل تصفية القائمة، جلب
  `bbox` عند تحريك الخريطة (مؤجَّل)، إدراج وتحديث مباشر، وقائمة نصية بديلة للعلامات.
- **البث المباشر (`src/lib/live.ts`):** يرسل `{"type":"auth"}` أولا ثم بعد كل تجديد للرمز، يعالج `ready`
  و`report.created` و`report.status_changed` و`media.stored`، إعادة اتصال بتأخير أُسّي مع عشوائية
  (equal jitter، من 1 ث إلى 30 ث)، الرمز 4401 ⇒ تجديد الرمز ثم إعادة الاتصال، 4403 ⇒ توقف وعرض «لا صلاحية»،
  مهلة انتظار `ready`، رسائل `ping` دورية، وإعادة اتصال فورية عند عودة التبويب أو الشبكة.
  تُحدَّث ذاكرة react-query مباشرة (`src/lib/liveCache.ts`).
- **اللغات:** العربية (افتراضية، RTL) والفرنسية (LTR) فقط. كل النصوص في `src/i18n/{ar,fr}.json` بمفاتيح متطابقة،
  تحديث `<html lang dir>` وحفظ الاختيار. التواريخ والأرقام عبر `Intl` بأرقام غربية (`-u-nu-latn`).
  CSS بالخصائص المنطقية فقط (inline/block) دون ملفات RTL مكررة.
- **المظهر وإمكانية الوصول:** وضع فاتح/داكن يتبع النظام مع زر تبديل (نظام ← فاتح ← داكن)، تركيز مرئي،
  رابط «انتقل إلى المحتوى»، تسميات ARIA، مناطق `aria-live` للحالات والبلاغات الجديدة، احترام
  `prefers-reduced-motion`. الألوان مقرونة دائما بنص (لا يُعتمد اللون وحده).

## التشغيل مع المكدس المحلي

1. شغّل المكدس من جذر المستودع (انظر `README.md` الرئيسي). تأكد أن `API_CORS_ORIGINS` في `.env` يتضمن
   `http://localhost:5173` (القيمة في `.env.example` الجذري تتضمنه)، فالخادم يرفض أيضا اتصالات WebSocket
   من أصل غير مسموح.
2. في هذا المجلد:

   ```bash
   cd apps/dashboard
   cp .env.example .env.local   # اختياري: القيم الافتراضية تناسب المكدس المحلي
   npm ci
   npm run dev                  # http://localhost:5173
   ```

| المتغير | الافتراضي | الدور |
|---|---|---|
| `VITE_API_BASE_URL` | `http://localhost:8000` | عنوان الـ API (يُشتق منه `ws://…/api/v1/staff/live`) |
| `VITE_OIDC_ISSUER` | `http://localhost:8080/realms/ehimaya-staff` | مُصدر الرموز |
| `VITE_OIDC_CLIENT_ID` | `ehimaya-dashboard` | العميل العام في Keycloak |
| `VITE_MAP_STYLE_URL` | فارغ | نمط MapLibre؛ إن كان فارغا تُستعمل بلاطات OpenStreetMap النقطية مع الإسناد |

المنفذ 5173 ثابت (`strictPort`) لأن عنوان إعادة التوجيه المسجل في Keycloak هو `http://localhost:5173/*`،
وصفحة العودة هي `/callback`. للنشر في الإنتاج يجب تسجيل العنوان الفعلي في العميل، وخدمة `dist/` مع إعادة
توجيه كل المسارات إلى `index.html`.

## إنشاء مستخدم اختبار في Keycloak

1. افتح لوحة الإدارة `http://localhost:8080/admin` وادخل بحساب المدير (`KEYCLOAK_ADMIN` / `KEYCLOAK_ADMIN_PASSWORD` من `.env`).
2. اختر realm **ehimaya-staff** ← **Users** ← **Create new user**:
   - Username (مثلا `operator.sfax`)، Email، First name، Last name (مطلوبة في ملف المستخدم).
   - **Gouvernorat / الولاية** (`gouvernorat_code`): رمز الولاية، مثلا `61` لصفاقس.
     لحساب وطني: اترك الولاية فارغة واختر **Scope / النطاق** = `national`.
   - Required user actions: اتركها، فـ `Configure OTP` و`Update Password` إجباريان افتراضيا في هذا الـ realm.
3. **Credentials** ← **Set password** بكلمة مؤقتة (Temporary = On) تحترم السياسة
   (8 أحرف، رقم، حرف كبير، رمز خاص).
4. **Role mapping** ← **Assign role** ← Filter by realm roles ← `operator`
   (أو `local_committee` لاختبار وضع القراءة فقط، أو دور غير معني مثل `content_editor` لاختبار صفحة «لا صلاحية»).
5. افتح `http://localhost:5173`: يُحوَّل المتصفح إلى Keycloak، وعند أول دخول يُطلب تغيير كلمة المرور ثم
   مسح رمز QR بتطبيق TOTP (FreeOTP أو Google Authenticator أو غيرهما) وإدخال الرمز المكوّن من 6 أرقام.

## الاختبارات والتحقق

```bash
npm run lint        # ESLint (typescript-eslint strict-type-checked + react-hooks)، صفر تحذيرات
npm run typecheck   # tsc -b --noEmit (strict، noUncheckedIndexedAccess)
npm test            # vitest run (jsdom)
npm run build       # tsc -b ثم vite build إلى dist/
```

تغطي الاختبارات (`src/**/*.test.ts(x)`): تطابق مفاتيح ar/fr والمتغيرات، تسميات الحالات الرسمية، جدول
الانتقالات و`allowed_transitions`، صلاحيات الأدوار وقراءة الرمز، عميل البث المباشر بمقبس وهمي (auth عند
الفتح، إعادة auth بعد التجديد، التأخير الأسي، 4401، 4403، مهلة ready، ping)، عميل الـ API (الرمز، 401 ⇒ تجديد
وإعادة محاولة واحدة، ترجمة رموز الأخطاء)، تحديث ذاكرة react-query بالأحداث، صفحة المؤشرات ببيانات وهمية،
صفحة التفاصيل (تحديث متفائل والتراجع عند 409، وضع القراءة فقط)، حارس الدخول، وتبديل اتجاه RTL/LTR.

يعمل التكامل المستمر في `.github/workflows/dashboard.yml`.

## حدود معروفة

- لم يُختبر الدخول الكامل مع Keycloak والـ API الحقيقيين آليا (يتطلب TOTP)؛ الاختبارات تستعمل خدمات وهمية.
  تم فقط التحقق يدويا من أن الـ API المحلي يقبل الأصل `http://localhost:5173` (CORS) ويغلق WebSocket
  برمز 4401 عند رمز غير صالح.
- الأدوار والنطاق تُقرأ من رمز الوصول (دون التحقق من التوقيع، فالخادم هو من يتحقق) لأغراض العرض فقط؛
  الخادم يبقى المرجع في التصفية الجغرافية والصلاحيات.
- الجلسة محفوظة في `sessionStorage` (تبويب واحد)؛ فتح تبويب جديد يمر بـ Keycloak (دون إعادة إدخال إن كانت
  جلسة SSO قائمة). انتهاء جلسة SSO (15 دقيقة خمول) يعيد التوجيه إلى صفحة الدخول.
- الخريطة تعرض حتى 400 بلاغ للمساحة المرئية (صفحتان × 200)، مع تنبيه للتقريب عند وجود المزيد؛ لا تجميع
  (clustering) للعلامات بعد.
- رمز المعتمدية يُعرض كرقم خام (`delegation_id` فارغ حاليا حسب العقد).
- البلاطات الافتراضية من `tile.openstreetmap.org` مخصصة للتطوير فقط؛ في الإنتاج يجب ضبط `VITE_MAP_STYLE_URL`
  على خادم بلاطات خاص.
- لا يتعامل العميل مع رموز الأخطاء النصية غير الموحدة في الخادم إلا عبر جدول أسماء مستعارة
  (`DETAIL_ALIASES` في `src/lib/api.ts`)؛ أي رمز جديد غير معروف يُعرض كرسالة عامة حسب رمز HTTP.
- `npm install` بإصدار npm 10.9.4 (المرفق مع Node 22.22) يفشل بخطأ داخلي في arborist
  (`Cannot read properties of null (reading 'edgesOut')`) عند إعادة حلّ الشجرة؛ `npm ci` يعمل. لتحديث
  ملف القفل استعمل `npx npm@11 install`.
