# تطبيق ء-حماية للهاتف (المرحلة 2)

تطبيق Flutter للمواطنين (Android و iOS) للتبليغ عن حالات الطوارئ لدى الحماية المدنية، مبني على
عقد الواجهة البرمجية [`docs/api/phase-2-contract.md`](../../docs/api/phase-2-contract.md).

- معرّف التطبيق (Android applicationId و iOS bundle id): `tn.ehimaya.app`
- الاسم: ء-حماية (بالعربية) و e-Himaya (بالفرنسية والإنجليزية)
- اللغات: العربية (افتراضية، من اليمين إلى اليسار)، الفرنسية، الإنجليزية

## محتوى التطبيق

| المتطلب | ما يوفره التطبيق |
|---|---|
| FR-A-001 | ميثاق الخصوصية وحماية المعطيات الشخصية (الإصدار `2026-10`) قبل أي شاشة أخرى، مع التذكير بالقانون الأساسي عدد 63 لسنة 2004 وبالمسؤولية القانونية عن البلاغات الكاذبة. خانة موافقة صريحة، حفظ محلي للإصدار، ثم `POST /api/v1/consents` عند توفر هوية (يُعاد لاحقا عند انقطاع الشبكة، ويُعاد إرساله عند `428 consent_required` ثم يُعاد البلاغ). |
| FR-A-002/003 | اختيار الصفة: مواطن أو مؤسسة. المؤسسة: شرح أن التسجيل وجوبي عبر بوابة المؤسسات (المرحلة 4) مع إمكانية الدخول فقط. المواطن: دون حساب، أو إنشاء حساب، أو الدخول. |
| التسجيل والدخول | Authorization Code + PKCE (S256) عبر `flutter_appauth` على Keycloak (فضاء `ehimaya-public`، العميل `ehimaya-mobile`، التسجيل بـ `prompt=create`). الرموز في `flutter_secure_storage`، تجديد آلي قبل انتهاء الصلاحية وعند 401، خروج مع إنهاء الجلسة في Keycloak. بعد أول دخول: استمارة استكمال الملف الشخصي (`PUT /api/v1/me/profile`) مع قائمتي الولايات والمعتمديات. |
| المجهول | مفتاح جهاز من 32 بايتا عشوائيا (`Random.secure`) بترميز base64url دون حشو، يُولَّد مرة واحدة ويُحفظ في التخزين الآمن، ويُرسل في `X-Device-Key` مع كل طلب للواجهة ولخادم tus (ولا يُرسل أبدا مع رمز Bearer). عند `403 anon_blocked` يظهر شريط يقترح إنشاء حساب. |
| NFR-09 | زر نجدة كبير في الرئيسية: نقرة للتسليح ونقرة للإرسال (أو ضغطة مطوّلة)، وزر عائم في بقية الشاشات الرئيسية (نقرة ثم تأكيد). يُرسل نداء `sos` بالموقع الحالي (أو آخر موقع معروف إن تأخر GPS) عبر الطابور المحلي. |
| FR-A-033 | أرقام الطوارئ 198 و190 و197 و193 (بيانات ثابتة في الشيفرة) تُطلب عبر `tel:` بالشريحة مباشرة، دون إنترنت ودون أي طلب للمنصة، ومتاحة من كل الشاشات وحتى قبل قبول الميثاق. |
| FR-A-040..047 | بلاغ جديد: شبكة الأصناف (دون `sos`)، نص اختياري بلغة الواجهة، تحديد الموقع آليا مع الدقة وخريطة (flutter_map) لضبط الدبوس، صور وفيديو (الكاميرا أو المعرض)، رسالة صوتية (5 دقائق كحد أقصى مع إيقاف آلي، مؤشر شدة الصوت، استماع، إعادة، حذف). الحفظ في الطابور المشفّر ورمز مؤقت `TMP-XXXXXX` فوري ثم المزامنة. |
| NFR-04 | قاعدة drift مشفرة بـ SQLCipher (مفتاح 32 بايتا في التخزين الآمن). محرك مزامنة عند التشغيل وعند عودة الشبكة ودوريا في الواجهة: إنشاء البلاغ (متساوي القوة عبر `client_uuid`، 200 و201 سواء)، ثم رفع الوسائط بعميل tus 1.0 خاص على dio (POST ثم PATCH بقطع 1 م.ب، و HEAD للاستئناف، وحفظ الرابط والإزاحة بعد كل قطعة)، تراجع أُسّي مع تشويش، الخادم هو المرجع عند التعارض مع الاحتفاظ بالنسخة المحلية. تُحذف الملفات المحلية فقط عندما يؤكد الخادم الحالة `stored`. |
| FR-A-032 | «بلاغاتي»: الطابور المحلي مدموجا مع `GET /api/v1/reports/mine`، رقاقات الحالات مترجمة، نسخ رمز المتابعة، السحب للتحديث، والمتابعة برمز `EH-…` عبر `GET /api/v1/reports/track/{code}` (دون هوية). |
| الإعدادات | اللغة (محفوظة)، المظهر (فاتح، داكن، حسب الهاتف)، الهوية الحالية، الملف الشخصي، الخروج، تغيير الصفة، إعادة قراءة الميثاق. |

إمكانية النفاذ: أهداف لمس ≥ 48 dp، تسميات Semantics وتلميحات لكل زر أيقونة، أيقونات اتجاهية تنعكس في
العربية، أرقام الهواتف والرموز تُعرض دائما من اليسار إلى اليمين.

## البنية

```
lib/
  main.dart, app.dart
  core/
    config/        AppConfig (‎--dart-define) والمزوّدات العامة
    auth/          الجلسة، عميل OIDC (flutter_appauth)، حالة الهوية
    identity/      مفتاح الجهاز للمجهول
    http/          عميل dio واحد (Bearer أو X-Device-Key)، رموز الأخطاء وترجمتها، نماذج العقد
    storage/       التخزين الآمن والتفضيلات
    db/            قاعدة drift + SQLCipher (app_database.g.dart مولّد)
    sync/          الطابور، محرك المزامنة، التراجع، الجدولة
    tus/           عميل tus 1.0
    consent/       الميثاق والموافقة
    location/ connectivity/ media/ settings/ routing/ ui/
  features/        charter, onboarding, profile, home, sos, emergency, report, reports, settings
  l10n/            app_ar.arb, app_fr.arb, app_en.arb (+ الملفات المولدة)
test/              اختبارات الوحدات والواجهات (دون جهاز)
```

الحالة بـ Riverpod، والتنقل بـ go_router مع حارس: الميثاق ← الصفة ← الهوية ← الرئيسية.

## التشغيل على المحاكي مع المنظومة المحلية

1. شغّل المنظومة من جذر المستودع (انظر [`README.md`](../../README.md)): الواجهة على 8000، Keycloak
   على 8080، tusd على 1080.
2. Keycloak يُصدر الرموز باسم المضيف `http://localhost:8080` ويرفض HTTP للعناوين «الخارجية» مثل
   ‎10.0.2.2. لذلك الطريقة المنصوح بها هي تمرير المنافذ إلى المحاكي ثم استعمال `localhost`:

```bash
cd apps/mobile
flutter pub get
adb reverse tcp:8000 tcp:8000
adb reverse tcp:8080 tcp:8080
adb reverse tcp:1080 tcp:1080
flutter run \
  --dart-define=API_BASE_URL=http://localhost:8000 \
  --dart-define=TUS_URL=http://localhost:1080/api/v1/uploads/ \
  --dart-define=OIDC_ISSUER=http://localhost:8080/realms/ehimaya-public
```

القيم الافتراضية دون أي ‎`--dart-define`:

| المتغير | القيمة الافتراضية |
|---|---|
| `API_BASE_URL` | `http://10.0.2.2:8000` |
| `TUS_URL` | `http://10.0.2.2:1080/api/v1/uploads/` |
| `OIDC_ISSUER` | `http://10.0.2.2:8080/realms/ehimaya-public` |
| `OIDC_CLIENT_ID` | `ehimaya-mobile` |
| `MAP_TILE_URL` | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` (مع إسناد OpenStreetMap ظاهر على الخريطة) |
| `MAP_ATTRIBUTION` | `© OpenStreetMap contributors` |

القيم الافتراضية بـ 10.0.2.2 تكفي للوضع المجهول (الواجهة و tus)؛ الدخول بحساب يتطلب الطريقة أعلاه.
رابط العودة بعد الدخول: `tn.ehimaya.app:/oauth2redirect`.

ملاحظات:
- HTTP غير المشفر مسموح به فقط في نسخة debug على Android ولـ `10.0.2.2` و`localhost`
  (`android/app/src/debug/res/xml/network_security_config.xml`)، وعلى iOS للشبكة المحلية فقط
  (`NSAllowsLocalNetworking`). على محاكي iOS استعمل `localhost` مباشرة.
- لاختبار الوضع دون شبكة: فعّل وضع الطيران، أرسل بلاغا (يظهر الرمز المؤقت فورا)، ثم أعد الشبكة:
  يُرسل البلاغ آليا ويُعوّض الرمز المؤقت برمز `EH-…`.

تغطي الاختبارات: عميل tus (الإنشاء، القطع، الاستئناف بـ HEAD بعد الانقطاع، رفض الإنشاء)، محرك المزامنة

## حدود معروفة

- **التشفير:** حزمة `sqlcipher_flutter_libs` أصبحت فارغة (‎0.7.0+eol) منذ `sqlite3` 3.x. التشفير يأتي
  من خطاف بناء `sqlite3` باختيار `source: sqlcipher` لـ Android و iOS في `pubspec.yaml`، ويتطلب تنزيل
  المكتبة المبنية من GitHub عند البناء. يرفض التطبيق فتح الطابور إن لم تتوفر SQLCipher
  (`PRAGMA cipher_version`). الاختبارات تستعمل SQLite النظام في الذاكرة دون تشفير.
- **iOS والفيديو:** العقد لا يقبل إلا `video/mp4`، بينما تسجّل كاميرا iPhone غالبا بصيغة ‎`.mov`
  (QuickTime). يرفض التطبيق هذه الملفات محليا برسالة مترجمة إلى أن يُضاف `video/quicktime` إلى العقد
  أو يُضاف تحويل للصيغة.
- **وسائط مرفوضة:** الوسائط المرفوضة تُخفى من `/reports/mine`؛ لذلك يعتبر التطبيق ملفا رُفع كاملا
  ولم يظهر في القائمة بعد 3 دورات مزامنة مرفوضا (يُحتفظ بالملف المحلي ولا يُعاد رفعه).
- **المزامنة في الخلفية:** تتم المزامنة عند التشغيل وعودة الشبكة ودوريا والتطبيق في الواجهة فقط؛ لا توجد
  بعد مهمة خلفية للنظام (WorkManager / BGTaskScheduler).
- **الخرائط دون شبكة:** البلاطات لا تُخزّن مسبقا؛ دون شبكة يعمل الموقع وGPS ولكن تظهر الخريطة فارغة.
- **الملف الشخصي:** الواجهة تطلب رقم بطاقة التعريف كاملا عند كل حفظ (‏`cin` إلزامي في `PUT`)،
  ولا يُعرض إلا آخر 4 أرقام المحفوظة.
- لم يُختبر البناء على جهاز أو محاكي حقيقي في بيئة التطوير الحالية (لا Android SDK ولا Xcode)؛ البناء
  الفعلي لـ APK يتم في التكامل المستمر.
